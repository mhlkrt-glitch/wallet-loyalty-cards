# Wallet — общие карты лояльности

Тёмный адаптивный сайт в стиле Apple Wallet: общий каталог карт, добавление/редактирование/удаление, поиск, сканирование распространённых штрихкодов через камеру, загрузка изображения из галереи и собственных фото карт магазинов.

## Уже настроено под твой Supabase

Файл `.env.example` уже указывает на имеющийся Supabase-проект `sait`:

- URL: `https://jojwgqgvumnagqfjqaoj.supabase.co`
- В клиенте используется публичный publishable key; он предназначен для фронтенда. Секретный/service-role ключ здесь не нужен и не должен попадать в браузер.
- SQL создания таблиц — `supabase/schema.sql`. Он создаёт отдельные таблицы `loyalty_cards` и `loyalty_stores`, не меняя существующие таблицы других приложений.

## Шаг 1. Создать таблицы

1. Открой https://supabase.com/dashboard/project/jojwgqgvumnagqfjqaoj/sql/new
2. Открой файл `supabase/schema.sql` из архива, скопируй всё его содержимое в SQL Editor и нажми **Run**.
3. Открой **Table Editor** и убедись, что появились `loyalty_cards` и `loyalty_stores`.

Это необходимо выполнить один раз, прежде чем сайт сможет сохранять карты. Важно: политики в этом MVP разрешают всем посетителям читать, добавлять, менять и удалять все общие карты. Не загружай личные данные. Для закрытой семейной группы перед публичным запуском добавь Supabase Auth и ограничения прав.

## Шаг 2. Запуск на компьютере

Требуется Node.js 20+.

```bash
npm install
cp .env.example .env
npm run dev
```

На Windows PowerShell, если `cp` недоступен, используй `Copy-Item .env.example .env`.

## Шаг 3. Публикация в Vercel без GitHub-плагина

Плагин GitHub для самой публикации не обязателен, но исходный код сначала нужно загрузить в репозиторий или развернуть через поддерживаемый способ загрузки файлов.

### Через веб-интерфейс Vercel и GitHub

1. Создай новый репозиторий на https://github.com/new, например `wallet-loyalty-cards`.
2. Загрузи содержимое архива (не сам ZIP как один файл) в корень репозитория и нажми Commit.
3. В Vercel открой https://vercel.com/new, выбери этот репозиторий и нажми Deploy.
4. Перед деплоем или в **Settings → Environment Variables** задай для Production, Preview и Development:
   - `VITE_SUPABASE_URL` = `https://jojwgqgvumnagqfjqaoj.supabase.co`
   - `VITE_SUPABASE_ANON_KEY` = публичный publishable key из `.env.example`
5. Запусти новый deployment после добавления переменных.

Vercel также можно настроить через CLI, если он установлен и выполнен вход:

```bash
npm install
npx vercel link
npx vercel env add VITE_SUPABASE_URL production
npx vercel env add VITE_SUPABASE_ANON_KEY production
npx vercel --prod
```

Введи значения переменных по приглашению CLI. Не добавляй `.env` в Git.

## Камера и галерея

- Для доступа к камере опубликованный сайт должен работать по HTTPS и получить разрешение браузера.
- Сканер использует ZXing для распространённых 1D/2D кодов. При плохом освещении или повреждении штрихкода номер можно ввести вручную.
- В MVP изображения хранятся как data URL в базе; для многих крупных изображений следует перейти на Supabase Storage.

## Фото магазинов

В разделе **Магазины** нажми значок изображения возле названия и выбери фото. Затем магазин можно выбрать в форме добавления карты.
